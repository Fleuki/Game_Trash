# Вторсырьё — план разработки

**Основание:** [GDD.md](./GDD.md) v0.1
**Режим:** соло, 12 недель до публикации на Яндекс Играх
**Расчёт нагрузки:** ~5 часов в день, 6 дней в неделю ≈ 30 ч/неделя ≈ 360 часов на MVP

Этот документ отвечает на вопрос «что делать завтра утром», а не «какой должна быть игра».
За «какой» отвечает GDD. Если они противоречат — прав GDD, а этот файл правится.

---

## 0. Как пользоваться планом

1. Работа нарезана на **срезы** (S0…S24). Срез = запускается и щупается руками.
2. У каждого среза есть **критерий готовности**. Не «код написан», а «я нажал и увидел».
3. Срез не начинается, пока предыдущий не закрыт. Никаких двух незакрытых срезов.
4. После каждого среза — прочитать свой же код целиком и сказать вслух, что там происходит.
5. Оценки в днях — это ориентир для контроля дрейфа, а не обещание. Просадка на 2 дня — норма,
   просадка на неделю — сигнал резать фичу.

**Контрольные точки** (разделы 4 и 5) — единственные места, где принимается решение
«продолжаем / режем / разворачиваемся». Между ними — не рефлексировать, а делать.

## 2. Неделя 0 — всё, что делается без движка

### 2.1 Экономика в таблице (приоритет №1, 1–2 дня)

Google Sheets, листы:

- **Materials** — цена, доля в потоке, вес загрязнения.
- **Machines** — цена, пропускная способность (ед/сек), точность, содержание.
- **Districts** — состав партии в процентах, объём, цена партии.
- **Sim** — построчно 30 дней: вход (ед), мощность линии (ед/день), переработано,
  брак, куча (нарастающим), доход, расход, баланс.

Проверить три сценария вручную:

| Сценарий | Что проверяем | Ожидание |
|---|---|---|
| «Жадный» — самые дорогие грязные партии | Не ломается ли экономика в плюс | Куча растёт быстрее денег |
| «Осторожный» — только бизнес‑центр | Не является ли скука доминирующей стратегией | Хватает на бронзу, не хватает на золото |
| «Идеальный» — оптимальная линия | Достижима ли платина | Достижима, но впритык, с 2–3 плохими днями |

Целевые кривые (калибруются, пока не сойдутся):

- Первый сортировщик (магнит, 800 ₽) — доступен к дню 5–7.
- Второй участок (5000 ₽) — доступен к дню 12–14, ощущается как жертва.
- Оптический (2500 ₽) — день 10–14, открывает раскопку свалки.
- Ежедневный доход к дню 20 ≈ 1500–2500 ₽ при расходах ≈ 600–900 ₽.
- Входящий поток растёт на **+4 % в день** — это и есть «поток чуть больше мощности».
  Коэффициент вынести в конфиг первым делом, крутить его придётся до релиза.

**Выход этапа:** файл `docs/economy.md` с итоговыми числами + ссылка на таблицу.
Числа из GDD (разделы 5 и 10) считаются черновыми до этого момента.

## 3. Технический фундамент

### 3.1 Стек

TypeScript (strict) + Vite + PixiJS 8. UI — обычный DOM поверх canvas, не Pixi:
панели рынка, отчёта и контрактов на HTML/CSS пишутся втрое быстрее и бесплатно
получают доступность и адаптив под мобилку.

### 3.2 Структура проекта

```
src/
  sim/                  # чистая логика. Не знает про Pixi, DOM, время ОС
    types.ts            # сущности мира
    world.ts            # создание и клонирование WorldState
    step.ts             # один тик: команды -> системы -> события
    rng.ts              # сид-генератор (mulberry32)
    systems/
      transport.ts      # движение по лентам, заторы, развилки
      machines.ts       # сортировщики, крафт
      contamination.ts  # чистота партий
      economy.ts        # деньги, контракты, отгрузка
      dayCycle.ts       # фазы дня, рост потока
      waste.ts          # куча, вывоз, раскопка
  config/               # весь баланс. Ни одного числа в sim/
    materials.ts
    machines.ts
    districts.ts
    contracts.ts
    balance.ts
  commands/
    types.ts            # union всех команд
    dispatch.ts         # валидация и постановка в очередь
  render/               # Pixi. Читает WorldState, не пишет в него
    app.ts
    gridLayer.ts
    itemLayer.ts        # пулинг спрайтов предметов
    machineLayer.ts
    fx.ts
  ui/                   # DOM-панели
  platform/
    save.ts             # сериализация WorldState
    yandex.ts           # SDK, изолирован за интерфейсом
  main.ts               # склейка: цикл, ввод, рендер
tools/
  headless.ts           # прогон N дней без рендера -> CSV
```

### 3.3 Пять правил архитектуры (из GDD §15, конкретизированы)

1. **Симуляция не импортирует ничего из `render/`, `ui/`, `platform/`.**
   Проверяется линт-правилом `import/no-restricted-paths`. Нарушил — сборка красная.
2. **Фиксированный шаг 60 Гц.** Ускорение времени = N шагов симуляции за кадр,
   **не** умножение `dt`. Иначе x4 даст другую физику заторов, чем x1.
   ```ts
   const STEP = 1 / 60;
   let acc = 0;
   function frame(dtSec: number) {
     acc += Math.min(dtSec, 0.25);          // защита от фризов вкладки
     while (acc >= STEP) {
       for (let i = 0; i < speedMultiplier; i++) step(world, drainCommands());
       acc -= STEP;
     }
     render(world, acc / STEP);              // интерполяция для плавности
   }
   ```
3. **Никакого `Math.random()` в `sim/`.** Только `world.rng`. Сид пишется в сейв.
   Прогон с одним сидом и одной последовательностью команд обязан давать одинаковый
   хэш состояния — это тест, а не пожелание.
4. **Изменения состояния только командами.** Обработчик клика создаёт
   `{ type: 'PLACE_MACHINE', cell, kind }`, кладёт в очередь; применяется на границе тика.
   Это даёт бесплатно: undo, реплей, отладку, и открывает кооп в следующей игре.
5. **Ни одного числа баланса в коде систем.** Всё через `config/`.

### 3.4 Модель данных (черновик, уточняется на S3–S7)

```ts
type MaterialId = 'pet' | 'aluminium' | 'glass' | 'organic';

interface Item {          // одна единица сырья на ленте
  id: number;
  material: MaterialId;
  cell: number;           // индекс клетки в сетке
  t: number;              // 0..1 — прогресс внутри клетки
  dirty: boolean;         // касалась органики
}

interface Cell {
  kind: 'empty' | 'belt' | 'splitter' | 'machine' | 'inlet' | 'outlet';
  dir: 0 | 1 | 2 | 3;     // направление выхода
  items: number[];        // id предметов, отсортированы по t по убыванию
  machineId?: number;
}

interface Machine {
  id: number;
  kind: MachineKind;
  cell: number;
  filter: MaterialId[];   // «что пропускать» — меняется в один клик
  buffer: number[];       // предметы внутри
  cooldown: number;       // тиков до следующей обработки
}
```

**Ключевое решение — заторы.** Предмет двигается на `speed * STEP` по `t`; при `t >= 1`
спрашивает у клетки следующую; если следующая занята (нет места за впередиидущим
предметом) — встаёт. Обратное давление возникает само и бесплатно даёт механику
«расчистить затор» из GDD §4. Альтернатива (предметы исчезают на входе занятой машины)
проще на день, но убивает опору «нашёл узкое место» — не рассматривается.

### 3.5 Формулы (первая редакция, калибруется по таблице)

**Чистота партии** на точке отгрузки:
```
purity = target / (target + Σ примесь_i × weight_i)      weight: обычная 1.0, органика 2.0
цена   = qty × basePrice × (purity ≥ threshold ? purityMult(purity) : 0.3) × craftMult
```

**Точность сортировщика** — падает от перегруза и путает похожее:
```
p = base
    − overloadK × max(0, входящийПоток/номинал − 1)     // скорость против точности
    − confusion[material][filterMaterial]                // стекло↔прозрачный ПЭТ, алюминий↔сталь
```
Матрица `confusion` живёт в `config/machines.ts` — это единственное место, где кодируется
«дешёвый сортировщик путает похожее» из GDD §6.

**Бой стекла:** при `beltSpeed > glassSafeSpeed` — шанс на тик превратить единицу стекла
в осколки; осколки едут дальше как примесь с `weight 1.5`. Один параметр, одна повадка.

## 4. Вертикальные срезы

Формат: **цель — что делаем — критерий готовности (щупается руками) — дни.**

### Фундамент

**S0. Каркас** — 1 д.
Vite + TS strict + Pixi, пустой canvas, фиксированный цикл, оверлей FPS/TPS/тик.
*Готово:* открыл localhost, вижу счётчик тиков, он ровно 60/сек, вкладка в фоне не ломает.

**S1. Сетка и камера** — 1.5 д.
Сетка 32×20, pan мышью и пальцем, zoom, подсветка клетки под курсором, координата в HUD.
*Готово:* могу таскать поле, тыкать в клетки, вижу правильные координаты на мобильном тачпаде.

**S2. Строительство лент** — 2 д.
Рисование конвейера протяжкой, автоповорот на изломах, удаление, «призрак» под курсором,
запись в `WorldState` командой.
*Готово:* нарисовал змейку из 30 клеток, стёр половину — состояние совпадает с картинкой.

### Поток

**S3. Один предмет едет** — 1.5 д.
Источник (inlet) спавнит предмет, он идёт по клеткам, на конце исчезает.
*Готово:* один кубик доехал от начала до конца, скорость ленты меняется ползунком.

**S4. Много предметов и затор** — 2 д.
Очередь внутри клетки, минимальная дистанция, обратное давление, визуально видимая пробка.
*Готово:* перекрыл конец ленты — очередь встала до самого входа, снял — поехала.

**S5. Стрелка‑развилка** — 2 д.
Делитель потока: гонит предметы попеременно в два выхода и обходит забитую сторону.
Материалы не различает — это работа сортировщиков (решение пересмотрено после КТ‑1, см. §8).
*Готово:* поток делится поровну, перекрытая ветка не останавливает линию.

**S6. Сортировщики** — 3 д.
Ручной стол, магнит, оптический: пропускная способность, буфер, точность, ошибки.
Ошибка визуально заметна (предмет уехал не туда).
*Готово:* поставил ручной стол — 85 % ПЭТ уходит в нужную сторону, 15 % мимо, и это видно глазами.

**S7. Загрязнение и чистота** — 2 д.
Приёмники фракций, накопление состава, расчёт чистоты, индикатор на приёмнике,
органика пачкает соседние фракции.
*Готово:* два одинаковых захода дают разную чистоту, и я могу объяснить почему.

> ### КОНТРОЛЬНАЯ ТОЧКА 1 — конец 4‑й недели
> Дать себе 20 минут поиграть без денег, без контрактов, без целей.
> **Вопрос:** хочется ли переставить сортировщик, чтобы чистота стала выше?
> Если нет — экономика этого не спасёт. Останавливаемся и чиним геометрию/заторы,
> даже ценой двух недель. Пропускать эту точку нельзя — это главный риск проекта.

*Готово:* экструдер окупается за N дней, N совпадает с таблицей ±20 %.

**S16. Участки и общие узкие места** — 3 д.

## 5. Инструменты отладки (делаются по ходу, не откладывать)

Каждый час, вложенный сюда, возвращает день на балансе.

- **Debug‑оверлей** (S0): тик, FPS, число предметов, длина очередей, загрузка каждой машины в %.
  Загрузка машин — главный инструмент поиска узкого места и в отладке, и потом в игре.
- **Скорость x100** (S9, только в dev): 30 дней за минуту.
- **Headless‑прогон** (`tools/headless.ts`, после S11): симуляция без Pixi, N дней,
  фиксированная политика игрока, вывод CSV → в ту же таблицу баланса.
  Это то, что заменяет «играть 30 дней вручную после каждой правки коэффициента».
- **Хэш состояния** (S9): `hash(WorldState)` каждые 600 тиков. Два прогона с одним сидом
  обязаны совпасть. Ловит недетерминизм в момент появления, а не через две недели.
- **Сид в UI**: поле ввода сида — воспроизводимый баг вместо «у меня иногда падает».

## 7. Производительность

Бюджеты — проверять на S4 и дальше, а не в конце:

| Параметр | Цель | Потолок |
|---|---|---|
| Предметов на экране | 400 | 800 |
| FPS десктоп | 60 | — |
| FPS слабый Android (4 ГБ, 2020 г.) | 60 | не ниже 30 |
| Тик симуляции при 800 предметах | < 3 мс | 8 мс |
| Размер бандла (gzip) | < 2 МБ | 5 МБ |

Приёмы: пул спрайтов (никаких `new Sprite` в кадре), один атлас текстур,
`ParticleContainer` для слоя предметов, культинг за пределами камеры,
предметы вне видимой области симулируются, но не рисуются.

Из открытых вопросов GDD: **1 предмет = 1 единица материала**, партия 200–400 единиц,
приезжает не мгновенно, а потоком в течение дня — это и держит пик в пределах 800.

## 8. Ответы на открытые вопросы GDD §18

Это рекомендации, а не решения за автора: несогласие фиксируется правкой GDD.

| Вопрос | Ответ | Почему |
|---|---|---|
| Объектов в партии | 1 предмет = 1 ед., партия 200–400, подача потоком | Держит бюджет рендера, партия «течёт» весь день |
| Правило на стрелке | Развилка **не различает материалы**: делит поток поровну и обходит забитую ветку | Первая редакция («по материалу») проверена на игроке и провалилась: три развилки за 20 минут дают 100 % чистоты и обесценивают все сортировщики. Опознание материала — работа машин, за неё в игре и платят |
| Визуальный стиль | Векторные силуэты, плоские формы, толстая обводка | Соло рисуется втрое быстрее пикселя, читается на 360 px, масштабируется без ассетов под DPI |
| Лимит конвейеров | Только место | Лимит уже есть: участок стоит 5000 ₽ + 100 ₽/день. Второй лимит — ложное обещание |
| Раскопка кучи | Режим разгрузочной площадки, не новая машина | Не плодит сущность, усиливает «одна разгрузка на всех» (§11) |
| Числа из §5 и §10 | Черновые до недели 0 | См. §2.1 |

## 9. Яндекс Игры — чеклист (S22, но читать заранее)

- SDK подключается **до** первого кадра; `LoadingAPI.ready()` вызывается, когда игра
  реально готова к вводу, а не когда загрузился JS.
- Сохранения: `player.setData` с дебаунсом (не чаще раза в 10–15 с и на конце дня),
  `localStorage` как резерв для незалогиненных. Сейв = сериализованный `WorldState` + сид.
- Реклама: межстраничная — на переходе день → утро, не чаще одного раза в 3 минуты
  и никогда на первом дне. Наградная — «ускоренный вывоз кучи» и «показать ещё одно
  предложение на рынке». **Обе награды обязаны быть полезны, но не обязательны** —
  иначе это ломает опору «регулятор сложности — сам игрок».
- Пауза симуляции на время показа рекламы и при потере фокуса вкладки.
- Никаких внешних запросов и сторонних CDN — только свои ассеты.
- Мобильный ввод с первого дня в S1: тап = клик, длинный тап = удаление, пинч = зум.
  Минимальная зона касания — 44 px, панели не перекрывают поле на 360×640.
- Проверить на реальном телефоне не позже конца 9‑й недели. Не в эмуляторе.

## 10. Арт: минимальный пайплайн

- **Стиль:** плоские силуэты, 4 материала = 4 узнаваемых формы + 4 цвета,
  различимые в оттенках серого (проверка на дальтонизм и на мелком масштабе).
- **Размер тайла:** 64 px, предмет 16–24 px.
- **Палитра:** грязный фон, чистые фракции — насыщенные. Визуальная награда за порядок
  работает на первую опору сильнее любого VFX.
- **Куча отходов** — единственный объект, на который не жалеем времени: она должна
  выглядеть унизительно.
- Всё рисуется в SVG → атлас. Никаких анимаций персонажей, только вращение,
  сдвиг ленты (текстурный скролл) и вспышка на ошибке сортировки.

## 11. Риски и что режем первым

| Риск | Признак | Ответ |
|---|---|---|
| Механика не интересна | Провал КТ‑1 | Две недели на геометрию и заторы. Если и это не помогает — проект закрывается на 6‑й неделе, а не на 12‑й |
| Заторы съедают время | S4 не закрыт за 4 дня | Упростить: фиксированные слоты в клетке вместо непрерывного `t` |
| Баланс не сходится | Куча растёт при любой стратегии | Крутить рост потока и цену вывоза, а не добавлять машины |
| Просадка на мобилках | < 30 FPS на 400 предметах | Партия 200 ед., упрощённый слой предметов, x4 без интерполяции |
| Соло‑выгорание | Два дня без коммита | Взять самый маленький незакрытый срез и закрыть его. Не начинать новое |
| Не успеваю к 12‑й неделе | Конец 8‑й недели, S16 не закрыт | Резать по списку ниже |

**Порядок резки (сверху — режется первым):**

1. S19 «новое в потоке» → переносится в первый патч после релиза.
2. Третий участок → два участка вместо трёх.
3. Экструдер → остаются пресс и компостер.
4. Районы: 5 → 3 (спальный, бизнес‑центр, стройка). Остальные — строчка в конфиге позже.
5. Свободный режим → в патч (но тогда обязательно написать «скоро» на экране сертификации).

**Не режется никогда:** заторы, загрязнение, куча, ускорение времени, отчёт за день.
Это и есть игра.

## 12. Дисциплина работы

**Git.** Ветка `claude/game-creation-plan-z7ufiu` для планов и документации;
разработка — по ветке на срез: `slice/03-item-moves`. Коммит осмысленный, а не «фикс».
В `main` попадает только то, что запускается.

**Definition of Done для среза:**

- [ ] Запускается, щупается руками, критерий готовности выполнен буквально
- [ ] Все числа — в `config/`, ни одного магического литерала в `sim/`
- [ ] `sim/` не импортирует рендер, DOM и платформу
- [ ] Прогон с одним сидом даёт одинаковый хэш
- [ ] Прочитал свой код целиком и могу объяснить каждую функцию
- [ ] Нет `TODO` внутри `sim/` — либо сделано, либо выписано в план

**Правила из GDD §19, применённые к коду:**

- Показал игроку — оно должно значить. Индикатор без смысла = баг.
- Чинить условием, а не числом. Перед правкой коэффициента — вопрос «а какое правило неверно?».
- Одна повадка на сущность. Машина с тремя поведениями — это три машины или одна лишняя.
- Список «сюда не лезу» (GDD §14) перечитывается каждый понедельник.
